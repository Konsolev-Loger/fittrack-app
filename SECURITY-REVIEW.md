# Проверка перед деплоем — 21.09.2026

Проверка исходников, зависимостей и локальных сценариев; не внешний пентест.
Публичного окружения пока нет. Отсутствие всех уязвимостей не гарантируется.

## Исправлено

- Helmet, no-store для API, лимит JSON 32 КБ, отказ от form-urlencoded.
- Проверка Origin для изменений; строгий FRONTEND_ORIGINS.
- 300 API-запросов/минуту/IP; 20 неудачных входов/регистраций за 15 минут/IP.
- Production проверяет origins и разные секреты длиной >=32.
- Access-токен только в памяти; старое persisted-состояние сбрасывается.
  Refresh-cookie HttpOnly, Secure в production, SameSite=Strict, path=/api/auth.
- Удалено логирование Axios-ошибок авторизации, способных содержать пароль.
- Ограничения входных данных и UTF-8 лимит bcrypt 72 байта для новых паролей.
- Seed больше не создаёт пользователя с известным паролем.
- .gitignore исключает секреты и копии БД; production-клиент использует /api, не localhost.
- Добавлены Vercel routing/headers, Dockerfile, проверка конфигурации перед публикацией и CI.

## Зависимости

Первый sandbox/offline-аудит показал нулевой результат, который не использован
как подтверждение безопасности. Онлайн-аудит обнаружил 9 уязвимых пакетов клиента
и 13 серверных (включая транзитивные).
Выполнены совместимые обновления; Prisma/client/adapter выровнены на 7.10.0.
Оставшиеся advisory устранены точечными overrides:
@prisma/config → deepmerge-ts 8.0.2; prisma → mysql2 3.24.4.
deepmerge-ts 8 меняет слияние Map; конфигурация проекта использует простые объекты.
Проверены загрузка конфигурации, генерация Prisma, сборка и интеграционные тесты.
Финальный онлайн npm audit: 0 известных уязвимостей в обоих проектах.
При обновлениях Prisma пересмотреть overrides. Не применять npm audit fix --force.
Release notes: https://github.com/RebeccaStevens/deepmerge-ts/releases/tag/v8.0.0

## Проверено локально

- 17 серверных и 11 клиентских тестов, обе сборки и lint клиента (22 сентября 2026).
- Чужие категории/упражнения/подходы/вес, logout, конкурирующие записи, даты.

- В браузере: публичная страница и форма входа на ширине 390 px. Личный интерфейс проверен сборкой, без входа в пользовательский аккаунт.

## Ограничения

Не выполнены независимый пентест, нагрузочный тест и аудит хостинга.
Нужно проверить TLS, права БД, proxy topology, backup/restore и изоляцию preview.
Rate limit хранится в памяти одного процесса, для нескольких нужен общий store.
Docker и GitHub Actions локально не запускались.
Существующая локальная БД не очищалась, старые тестовые пользователи не удалялись.
Статус подготовки и порядок публикации: DEPLOYMENT.md.

## Подтверждение почты и восстановление пароля

Реализованы одноразовые случайные 256-битные токены с SHA-256 в базе.
Подтверждение действует 24 часа, сброс — 30 минут. Потребление токенов и отзыв
сессий атомарны; вход сериализован со сбросом пароля блокировкой пользователя.
Проверены неверное назначение, повторное использование, истечение срока,
конкурирующие сбросы, отзыв прежних сессий и ограничение повторной отправки.
Токены в ссылках используют URL-фрагмент и не попадают в HTTP access logs.
GET не подтверждает адрес автоматически, необходим POST из формы.
Preview запрещён в production; файлы писем исключены из Git и Docker.
Реальная доставка SMTP не проверена: сервис ещё не подключён. Настройки — EMAIL-SETUP.md.
Почтовые функции временно отключены по запросу: EMAIL_AUTH_ENABLED и VITE_EMAIL_AUTH_ENABLED
по умолчанию false. Подтверждение не требуется, почтовые API недоступны, SMTP не требуется
для production. Код и тесты включённого режима сохранены. Адреса не помечаются подтверждёнными автоматически.
